# AiMenu 项目开发全记录 (模型训练与验证测试)

本文档记录了 AiMenu 从构思到最终测试验证的全过程。

---

## 1. 需求分析与选型 (Day 1)
*   **目标**: 打造一个能够理解复杂语义、支持地理校验的工业级点餐 Agent。
*   **模型选型**: 评估了 GPT-4o 和 Qwen-Plus。考虑到响应速度与中文语境的适配，最终选择了 **Qwen-Plus (通义千问)**。
*   **向量库**: 选择了本地持久化的 **ChromaDB**，降低运维成本。

## 2. 环境初始化 (Day 2)
*   **中间件**: 使用 Docker 搭建 MySQL 8.0 和 Redis 7.0。
*   **数据结构**: 确定了 `menu_items` 必须包含 `spice_level` 和 `allergens` 字段，以支持细粒度的 AI 筛选。
*   **数据初始化**: 最终整理了 1060 道菜品数据，覆盖川、粤、浙、闽等主流菜系，并编写 `setup_db.py` 完成冷启动与向量同步。

## 3. RAG 检索链路搭建 (Day 3)
*   **初版**: 仅使用向量搜索，搜“回锅肉”时有时会因为语义相近把“肉末茄子”排到前面。
*   **改进**: 引入 **BM25 算法** 做关键词强匹配，再用 RRF 合并两路召回。
*   **精排**: 加入 **DashScope Rerank**（`qwen3-vl-rerank`）对候选精排；额度受限时可切本地 `bge-reranker-v2-m3`。
*   **测试**: 该阶段在 153 道菜品、150 条标注上复测，纯向量 Top-3 Recall 0.9733，混合检索 0.9933、MRR 0.9789。
    （历史阶段数据：语料后来扩到 1060 道、标注扩到 585 条四类分层，`text-embedding-v4` 下同一链路 Top-3 0.9060、
    Top-1 0.8171、MRR 0.8564；当前 v3 为 0.9043 / 0.8120 / 0.8524，详见 docs/evaluation.md；两组不可直接比较。）

## 4. LangGraph Agent 开发 (Day 4)
*   **意图识别**: 编写 System Prompt，将意图划分为：菜单咨询、配送校验、订单查询、通用闲聊。
*   **工具绑定**: 在 `agent/tools.py` 中把底层 `amap_tool` / `db_tool` / 检索链路封装为三个 LangChain Tools：`search_menu`、`check_delivery`、`query_order`。
*   **状态流转**: 解决了 Agent 在没有地址时误调用配送工具的问题（增加了前置校验逻辑）。

## 5. 安全与一致性优化 (Day 5)
*   **鉴权**: 实现 JWT 登录墙，使用 `bcrypt` 对密码进行哈希处理。
*   **缓存**: 针对菜单列表，实现了 **Redis 延迟双删策略**。
*   **前端**: 开发 Vue 3 界面，实现流式输出 (SSE) 渲染。

## 6. 验证与测试记录 (Day 6)

### 测试用例 1: 复杂语义理解
*   **输入**: "我今天胃口不太好，想吃点清淡的，不要太贵。"
*   **AI 决策**: 调用 `search_menu(query="清淡, 便宜")`。
*   **结果**: 推荐了“番茄炒蛋 (¥22)”和“广式肠粉 (¥15)”，符合预期。

### 测试用例 2: 配送范围拦截
*   **输入**: "我在北京天安门，能送吗？" (餐厅在武汉)
*   **AI 决策**: 调用 `check_delivery(address="天安门")`。
*   **结果**: 地图 API 返回距离约 1000km，AI 礼貌告知超出范围（限定 10km 内）。

### 测试用例 3: 鉴权与安全
*   **动作**: 尝试在未登录状态下通过 Postman 直接请求 `/chat`。
*   **结果**: 返回 `401 Unauthorized`，登录墙生效。

---

## 7. 最终结论
项目已完成从中间件部署、RAG 链路优化、Agent 状态机构建到前端联调的全流程。检索、拒答、Agent 与压测指标均基于本地 1060 道菜的模拟语料和单机压测，用于链路验证与回归对比，不代表线上规模效果。
